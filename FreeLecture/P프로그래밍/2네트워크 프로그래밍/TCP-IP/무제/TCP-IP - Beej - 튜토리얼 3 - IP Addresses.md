##### 3.1 IP 주소: 버전 4와 6

옛날 옛적, 벤 케노비가 오비완 케노비로 불리던 시절에는 IPv4라고 불리는 멋진 네트워크 라우팅 시스템이 있었습니다. IPv4 주소는 4바이트(일명 "옥텟")로 구성되어 있고, 일반적으로 `192.0.2.111` 같은 점과 숫자의 형태로 표현됩니다.

이건 아마 어디선가 본 적 있을 겁니다.

사실, 이 문서를 쓰는 현재 기준으로, 거의 모든 인터넷 사이트가 여전히 IPv4를 사용하고 있습니다.

모두가 행복했습니다. 오비완도, 여러분도, IPv4도. 그런데 어떤 비관주의자, 빈트 서프라는 사람이 나타나서 "IPv4 주소가 곧 고갈될 거야!"라고 경고했습니다.

(참고로, 빈트 서프는 인터넷의 아버지로도 잘 알려져 있습니다. 그러니 그의 판단을 의심할 입장은 아니죠.)

"주소가 고갈된다고? 말도 안 돼! 32비트 주소면 억 단위 주소가 있는데 설마 컴퓨터가 그렇게 많단 말이야?"

맞습니다.

초기에는 컴퓨터가 많지 않았기 때문에, 몇몇 대형 기관들(예: Xerox, MIT, Ford, HP, IBM, GE, AT&T, Apple 등)에 수백만 개의 주소가 후하게 할당되었습니다.

사실, 여러 임시방편이 없었다면 우리는 훨씬 전에 주소를 다 써버렸을 겁니다.

하지만 이제는 시대가 바뀌어, 인간 한 명, 컴퓨터 한 대, 계산기, 전화기, 주차 미터기, 심지어 강아지 한 마리까지 IP 주소가 필요한 세상입니다.

그래서 탄생한 것이 **IPv6**입니다. 빈트 서프는 아마 영원히 살 거고, 혹시 그의 육체가 사라지더라도 그는 인터넷 어딘가의 고지능 챗봇(예: ELIZA)으로 존재하고 있을지도 모릅니다. 아무튼, 그가 "내가 그랬잖아!"라고 말하지 않게 하려면 더 많은 주소가 필요합니다.

얼마나 더 많이 필요할까요?

단순히 두 배, 억 배, 조 배가 아닌 **7.9천만 억 조** 개의 주소가 필요합니다. 이 정도면 충분하겠죠?

"비즈(Beej), 그게 진짜야? 나는 큰 숫자는 못 믿겠어."라고 하실지도 모르겠군요. 32비트는 약 40억 개의 주소(2³²), 128비트는 약 340언저리의 '조 조 조' 개(2¹²⁸)의 주소를 제공합니다. 이는 우주에 존재하는 별 하나마다 수백만 개의 IPv4 인터넷을 줄 수 있다는 뜻입니다.

IPv4는 점(dot)과 숫자의 조합이지만, IPv6는 16진수로, 두 바이트씩 콜론(:)으로 구분합니다:

```
2001:0db8:c9d2:aee5:73e3:934a:a5ae:9551
```

여기서 0이 많은 경우는 "::"로 압축 가능하며, 각 부분의 선행 0은 생략할 수 있습니다:

```
2001:0db8:c9d2:0012:0000:0000:0000:0051 → 2001:db8:c9d2:12::51  
2001:0db8:ab00:0000:0000:0000:0000:0000 → 2001:db8:ab00::  
0000:0000:0000:0000:0000:0000:0000:0001 → ::1
```

`::1`은 루프백 주소로, 현재 실행 중인 기계를 의미합니다. IPv4에서는 `127.0.0.1`이 이에 해당합니다.

IPv4 호환 IPv6 주소 형식도 있습니다. 예: `192.0.2.33` → `::ffff:192.0.2.33`

이건 정말 **진지하게 재밌는** 겁니다.

IPv6 설계자들은 수조 개의 주소를 예약용으로 잘라냈지만, 어차피 남는 게 넘쳐나기 때문에 아무도 신경 쓰지 않습니다. 은하계의 모든 인간, 강아지, 주차 미터기에 IP 주소를 줄 수 있습니다. 은하계엔 주차 미터기가 반드시 존재하거든요. 정말입니다.

### **3.1.1 서브넷 (Subnets)**

조직적 관리 목적상, IP 주소의 일부를 네트워크 부분으로, 나머지를 호스트 부분으로 지정하는 경우가 있습니다.

예: IPv4 주소 `192.0.2.12`가 있다고 하면, 앞의 3바이트는 네트워크, 마지막 1바이트는 호스트라고 지정할 수 있습니다. 즉, `192.0.2.0` 네트워크의 호스트 12번이 되는 거죠.

옛날에는 주소의 첫 1~3바이트를 네트워크로 지정하는 "클래스 기반 서브넷"이 존재했습니다:

- **Class A**: 1바이트 네트워크 + 3바이트 호스트 (약 1,600만 대 호스트 가능)
    
- **Class C**: 3바이트 네트워크 + 1바이트 호스트 (약 256대 호스트)
    

Class A는 희귀했고, Class C는 많았으며, Class B는 그 사이에 있었습니다.

서브넷을 정의할 때는 **넷마스크(Netmask)**를 사용합니다. 이 값과 IP 주소를 비트 단위로 AND 연산하면 네트워크 주소를 얻을 수 있습니다. 예:  
`192.0.2.12 AND 255.255.255.0 = 192.0.2.0`

하지만 이 방식은 충분히 유연하지 못했습니다. Class C는 빨리 고갈됐고, Class A는 더 이상 없었습니다. 그래서 비트 수를 자유롭게 지정할 수 있는 **CIDR (Classless Inter-Domain Routing)** 방식이 도입됐습니다. 예:  
`192.0.2.12/30` → 30비트는 네트워크, 2비트는 호스트 (총 4개 호스트 가능)

IPv6에서도 비슷하게 사용됩니다:  
`2001:db8::/32`, `2001:db8:5413:4028::9db9/64`

### **3.1.2 포트 번호**

이전에 소개한 **계층형 네트워크 모델** 기억나시죠? IP는 인터넷 계층이고, TCP/UDP는 호스트 간 전송 계층입니다.

IP 주소 외에 TCP와 UDP가 사용하는 주소가 하나 더 있습니다. 바로 **포트 번호**입니다. 이는 16비트 숫자로, 로컬 주소의 일종입니다.

비유하자면, IP 주소가 호텔 주소라면, 포트는 방 번호입니다.

예: 메일과 웹 서비스를 동시에 처리하려면?  
→ IP 주소는 같지만 포트 번호를 다르게 설정합니다.

인터넷의 각 서비스는 고유한 **포트 번호**를 가집니다. 일부 예시는 다음과 같습니다:

- HTTP: 포트 80
    
- Telnet: 포트 23
    
- SMTP: 포트 25
    
- DOOM 게임: 포트 666
    

포트 번호 1024 이하(0~1023)는 특별한 포트로, 시스템 권한이 있어야 사용할 수 있습니다.

### **3.2 바이트 순서(Byte Order)**

"왕국의 명에 따라, 두 개의 바이트 순서가 존재한다! 그 이름은… 쿨하지 않은 것(Little)과 멋진 것(Big)이다!"

장난처럼 들리지만, 실제로 한 쪽이 더 낫습니다. :-)

사실을 말하자면, 여러분의 컴퓨터는 바이트를 반대 순서로 저장할 수 있습니다. 그게 바로 **Endian 문제**입니다.

네트워크에서는 일반적으로 큰 바이트가 앞에 오는 **Big-Endian** 방식이 사용됩니다. 예: `0xb34f` → `b3 4f` 순서

하지만 Intel 프로세서 기반 시스템은 **Little-Endian**을 사용합니다: `0xb34f` → `4f b3`

- **Big-Endian** = **Network Byte Order**
    
- **Host Byte Order** = 시스템마다 다름 (Intel은 Little, PowerPC는 둘 다 가능)
    

그래서, 항상 **네트워크로 데이터를 보낼 땐 Network Byte Order로 변환**해야 하고, **수신 시엔 다시 Host Byte Order로 변환**해야 합니다.

다행히도 이를 도와주는 함수들이 있습니다:

|함수|설명|
|---|---|
|`htons()`|Host → Network (Short)|
|`htonl()`|Host → Network (Long)|
|`ntohs()`|Network → Host (Short)|
|`ntohl()`|Network → Host (Long)|

### **3.3 구조체 (structs)**

이제 본격적으로 **프로그래밍** 얘기를 해봅시다. 여기서는 소켓 인터페이스에서 사용하는 주요 데이터 타입들을 살펴봅니다.

#### **소켓 디스크립터**

```c
int
```

그냥 일반적인 정수입니다.

---

#### **`struct addrinfo`**

호스트 이름 및 서비스 이름을 IP 주소로 변환하거나 소켓 주소를 설정할 때 사용됩니다.

```c
struct addrinfo {
    int              ai_flags;
    int              ai_family;
    int              ai_socktype;
    int              ai_protocol;
    size_t           ai_addrlen;
    struct sockaddr *ai_addr;
    char            *ai_canonname;
    struct addrinfo *ai_next;
};
```

- `ai_family`: `AF_INET`(IPv4), `AF_INET6`(IPv6), `AF_UNSPEC`
    
- `ai_socktype`: `SOCK_STREAM`(TCP), `SOCK_DGRAM`(UDP)
    
- `ai_addr`: `sockaddr_in` 또는 `sockaddr_in6` 포인터
    

`getaddrinfo()` 함수 호출 시 이 구조체를 설정하고, 반환된 연결 리스트를 통해 사용합니다.

---

#### **`struct sockaddr`**

모든 종류의 소켓 주소 정보를 담는 범용 구조체입니다.

```c
struct sockaddr {
    unsigned short sa_family;
    char           sa_data[14];
};
```

`sa_family`는 주소 계열 (`AF_INET`, `AF_INET6`)을 나타냅니다.

---

#### **`struct sockaddr_in` (IPv4용)**

```c
struct sockaddr_in {
    short int          sin_family;
    unsigned short int sin_port;
    struct in_addr     sin_addr;
    unsigned char      sin_zero[8];
};
```

- `sin_family`는 `AF_INET`으로 설정
    
- `sin_port`는 `htons()`로 변환 필요
    
- `sin_zero`는 `memset()`으로 0으로 초기화
    

---

#### **`struct in_addr` (IPv4 주소)**

```c
struct in_addr {
    uint32_t s_addr;
};
```

IPv4 주소는 4바이트이며, `ina.sin_addr.s_addr`처럼 접근할 수 있습니다.

---

#### **`struct sockaddr_in6` (IPv6용)**

```c
struct sockaddr_in6 {
    u_int16_t       sin6_family;
    u_int16_t       sin6_port;
    u_int32_t       sin6_flowinfo;
    struct in6_addr sin6_addr;
    u_int32_t       sin6_scope_id;
};

struct in6_addr {
    unsigned char s6_addr[16];
};
```

IPv6 주소와 포트를 포함합니다. `flowinfo`나 `scope_id`는 초보 단계에선 무시해도 됩니다.

---

#### **`struct sockaddr_storage`**

IPv4 또는 IPv6 주소를 저장할 수 있도록 충분히 큰 구조체입니다.

```c
struct sockaddr_storage {
    sa_family_t ss_family;
    ...
};
```

사용할 주소 종류를 모르거나 범용적으로 처리하고 싶을 때 사용합니다.

---
